## 二、当前问题分析

### 2.1 现有触发机制的局限性

| 触发方式 | 优点 | 缺点 |
|---------|------|------|
| **基于意图识别** | 语义理解强 | 依赖模型性能，边界模糊时误判 |
| **基于关键词匹配** | 简单高效 | 无法理解上下文，语义缺失 |
| **基于置信度阈值** | 可量化可控 | 阈值难以确定，动态适应差 |
| **基于历史模式** | 个性化体验 | 冷启动问题，隐私考量 |

### 2.2 具体场景问题

**场景 1：单一维度误触率高**
- 用户："今天天气不错，要不要去田里看看？"
- 关键词匹配检测到"田"，触发病虫害检测技能
- 实际用户只是闲聊，无需专业技能

**场景 2：复杂意图理解不足**
- 用户："我家的稻叶子发黄，是不是有病了？"
- 单一意图识别可能只匹配到"疾病诊断"
- 忽略了"稻叶子"这个关键上下文，应该触发病虫害检测

**场景 3：多模态输入处理不当**
- 用户上传一张病虫害图片，但文本描述不清楚
- 仅基于文本分析可能导致漏触
- 缺乏图片信号的触发通道

## 三、技术方案

### 3.1 核心概念：多维度特征融合

通过综合分析多个维度特征，实现更精准的技能触发决策：

**核心触发维度**：
- **意图匹配度**：LLM 分类 / 向量相似度
- **关键词密度**：TF-IDF / 正则匹配
- **模型置信度**：Logit 分析 / 多次投票
- **历史模式**：对话历史 N-gram / 用户画像
- **上下文相关性**：滑动窗口 / 主题连贯性
- **多模态信号**：图片存在性 / 类型检测

### 3.2 多维触发系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                    用户输入 (User Input)                     │
│              (文本 + 图片 + 上下文历史)                       │
└───────────────────────┬─────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────────┐
│              多维特征提取器 (Feature Extractor)              │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐         │
│  │ 意图识别器  │  │ 关键词匹配器│  │ 置信度分析器│         │
│  └─────────────┘  └─────────────┘  └─────────────┘         │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐         │
│  │历史模式分析器│  │ 上下文分析器│  │ 多模态分析器│         │
│  └─────────────┘  └─────────────┘  └─────────────┘         │
└───────────────────────┬─────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────────┐
│           触发决策引擎 (Trigger Decision Engine)             │
│  • 特征权重动态调整 (Dynamic Weight Adjustment)              │
│  • 触发条件综合评估 (Comprehensive Evaluation)               │
│  • 置信阈值自适应 (Adaptive Threshold)                       │
└───────────────────────┬─────────────────────────────────────┘
                        │
                        ▼
              技能加载 / 工具调用 / 响应生成
```

### 3.3 触发决策公式

```
TriggerScore = Σ (Feature_i × Weight_i × ContextModifier_i)

触发条件：
- TriggerScore > AdaptiveThreshold
- 或 (任一维度 > EmergencyThreshold AND 其他维度 > MinThreshold)

其中：
- AdaptiveThreshold 动态调整：基于历史准确率、用户反馈
- EmergencyThreshold = 0.9（紧急触发阈值）
- MinThreshold = 0.3（最低支持阈值）
```

## 四、实现思路

### 4.1 项目现有基础

| 现有模块 | 功能 | 复用方式 |
|---------|------|---------|
| `DynamicToolMiddleware` | 会话级工具管理 | 扩展多维触发逻辑 |
| `SkillMiddleware` | 技能描述注入 | 增加触发评估钩子 |
| `SkillRegistry` | YAML 技能配置 | 扩展支持触发策略配置 |
| LLM 接口 | 意图识别 | 复用进行意图分析 |

### 4.2 实现步骤概览

**步骤 1：定义触发数据模型**
- 新建 `src/agents/trigger/trigger_models.py`
- 定义 `TriggerDimension` 枚举
- 定义 `TriggerFeatures` 数据类
- 定义 `TriggerConfig` 配置类

**步骤 2：实现特征提取器**
- 新建 `src/agents/trigger/feature_extractor.py`
- 实现意图识别特征提取
- 实现关键词匹配特征提取
- 实现置信度分析特征提取
- 实现历史模式分析

**步骤 3：实现触发决策引擎**
- 新建 `src/agents/trigger/trigger_engine.py`
- 实现动态权重调整算法
- 实现综合触发评分计算
- 实现自适应阈值机制

**步骤 4：实现多维触发中间件**
- 新建 `src/agents/middleware/multi_dimensional_trigger.py`
- 实现中间件接口
- 集成特征提取器和决策引擎
- 实现触发历史记录

**步骤 5：扩展 YAML 配置**
- 为每个技能增加 `trigger_config` 配置
- 支持技能特定的触发策略

**步骤 6：集成到 Agent**
- 修改 `orchestrator_agent_v2.py`
- 在技能加载前调用触发评估

### 4.3 配置示例

```yaml
# src/agents/skills/configs/detection.yaml

pest_detection:
  name: "病虫害检测技能"
  description: "识别农作物病虫害并提供防治建议"

  # 多维触发配置
  trigger_config:
    enabled: true
    strategy: "multi_dimensional"

    # 各维度触发条件
    conditions:
      intent:
        enabled: true
        threshold: 0.7
        patterns: ["病虫害识别", "病害检测"]

      keyword:
        enabled: true
        threshold: 0.5
        keywords: ["虫子", "病斑", "枯萎", "发黄", "虫害"]

      confidence:
        enabled: true
        threshold: 0.75

      multimodal:
        enabled: true
        require_images: true
        image_types: ["jpg", "png", "jpeg"]

      history:
        enabled: true
        window_size: 5
        relevance_threshold: 0.4

    # 权重配置
    weights:
      intent: 0.35
      keyword: 0.25
      confidence: 0.2
      multimodal: 0.15
      history: 0.05
```

## 六、专利权利要求建议

### 6.1 独立权利要求（主权利要求）

> 一种基于多维度特征融合的智能体技能触发方法，其特征在于，包括：
>
> 1. **多维特征提取步骤**：从用户输入和对话上下文中提取至少 3 个维度的触发特征，所述触发特征包括意图匹配度、关键词密度、模型置信度、历史对话模式、上下文相关性、多模态信号中的至少 3 种；
> 2. **动态权重分配步骤**：为每个触发特征分配动态权重，所述权重根据历史触发表现、用户反馈和场景特征进行自适应调整；
> 3. **综合评分步骤**：基于各触发特征和对应权重，计算综合触发分数；
> 4. **自适应阈值判断步骤**：根据历史准确率和当前上下文，动态计算自适应触发阈值；
> 5. **触发决策步骤**：当综合触发分数超过自适应触发阈值时，触发技能加载；
> 6. **紧急触发步骤**：当任一主要触发维度超过紧急阈值且其他维度满足最低要求时，直接触发技能加载。
