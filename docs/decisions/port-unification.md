# 端口统一决策

## 决策背景

### 原始端口方案

最初，各服务使用分散的端口配置：

| 服务 | 原端口 | 问题 |
|------|--------|------|
| 前端应用 | 3000 | 无问题 |
| 后端主服务 | 8080 | 与常用端口 8080 冲突风险 |
| 病虫害检测 | 8000 | 独立端口 |
| 大米品种识别 | 8001 | 独立端口 |
| 奶牛检测 | 8002 | 独立端口 |
| 规划咨询服务 | 8003 | ~~已废弃 - RAG 已集成到主 Agent~~ |

### 存在的问题

1. **端口冲突风险**
   - 8080 是常用端口（如 Tomcat 默认端口）
   - 多个检测服务端口分散（8000-8002）

2. **文档不一致**
   - 不同文档中的端口配置可能不同
   - 更新端口需要修改多处

3. **记忆负担**
   - 开发者需要记住多个端口
   - 新人上手困难

4. **部署复杂**
   - 防火墙需要开放多个端口
   - Docker 端口映射配置复杂

---

## 决策方案

### 新端口规范

制定统一的端口分配规范：

| 服务 | 新端口 | 说明 |
|------|--------|------|
| **前端应用** | 3001 | 前端服务（3000-3999 段） |
| **后端主服务** | 8081 | 后端服务（8000-8999 段），包含 RAG 知识库 |
| **检测服务网关** | 8001 | 统一检测服务 |

### 端口分配原则

1. **前端服务**：3000-3999
   - 3001：Next.js 应用

2. **后端服务**：8000-8999
   - 8000：预留（可用于其他服务）
   - 8001：检测服务网关（统一）
   - 8002：预留（可用于其他服务）
   - 8081：后端主服务（包含 RAG 知识库）

3. **避免冲突**
   - 不使用 8080（与 Tomcat 等常用）
   - 不使用 3000（避免与其他前端冲突）

## 配置位置

### 环境变量

```bash
# .env
PORT=8081                          # 后端主服务
HOST=127.0.0.1                     # 监听地址
ALLOWED_ORIGINS=http://localhost:3001  # CORS 配置
```

### 各服务配置

**后端主服务** (`service/settings.py`)：
```python
PORT = 8081
```

**检测服务网关** (`src/algorithms/api/main.py`)：
```python
PORT = 8001
```

**前端应用** (`frontend/package.json`)：
```json
{
  "scripts": {
    "dev": "next dev -p 3001"
  }
}
```

## 权衡和代价

### 优点

1. 端口分配有明确原则
2. 避免常用端口冲突
3. 降低维护成本
4. 改善开发体验

### 缺点

1. **迁移成本**：需要更新配置和文档
   - 缓解：一次性完成，后续稳定

2. **记忆更新**：开发者需要记住新端口
   - 缓解：更易记忆（8081 vs 8080）
